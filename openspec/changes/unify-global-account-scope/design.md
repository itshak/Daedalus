# Shared working context
Use a single account-ID scope model (all, explicit selected IDs, one ID), intersected with current authorized account inventory. Display player/world, disambiguate collisions with existing helper; never use nickname or email as identity. Store only selection preference under current operator/controller identity, not account/game payloads; clear on logout or controller change. Default all for fresh context; empty explicit selection stays empty, never silently expands to all. Persist across navigation and refresh, reconcile deleted or inaccessible IDs. Header popover visible across pages; explicit manage-all navigation for global account administration, settings global unless account-specific. Native shell equivalent with same semantics.
Inventory, overview aggregates, warehouses, production, military, reports and activity must be scoped and expose partial/unavailable data. Cancel stale requests or key all responses to account scope, selected target and generation; prevent late response contamination. Single-target editors auto-select when only one eligible account exists, otherwise offer only scoped eligible accounts. City list belongs to selected account, keyed by account plus city ID. On scope change discard out-of-scope targets, dependent city fields, previews, confirmation and queued review tokens; no stale execution. Multiple-account operations freeze explicit reviewed account/city targets, never expand as new accounts appear. Global scope is convenience, not authorization: all server-side ownership and existing reviewed dispatch checks remain. Provide clear target count, scope and unavailable reasons. Scope change never stops running operations. Preserve existing route compatibility, translations, responsive keyboard-accessible design.
