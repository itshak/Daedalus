# Design — monitor only the current IkaBot engine owner

Engine IPC offers `validate_session_existing` for an exact world/player. It selects the already authenticated in-memory object via the `_existing_session` method and never calls `Session.from_saved`. Only a read-only world GET to the verified fixed HTTPS host can be sent. The engine requires a 200 response, expected world redirect destination, a valid game marker and no known expired/rotated session indicators; it returns only `session_valid` with sanitized world/player identity (never game HTML/cookies/headers).

The backend `ExistingIPCClient.validate_account` remains read-only and checks `has_account` and the returned identity. The new opt-in CLI flag `--monitor-existing-sessions` requires the opt-in existing-session task mode. It binds one `TaskController(active_validation=True)`, `AssistanceBroker` and `ExistingSessionRecoveryMonitor` to the exact same `AccountSessionCoordinator`. Defaults remain strictly unchanged. The controller refuses task dispatch when it has an attached lease in a nonauthenticated phase or validation fails.

Operators explicitly consent to `POST /api/v1/accounts/{id}/monitor` with exactly `{"confirmed": true}`. Only when the current in-memory IkaBot world is verified does the backend hold its own host-local lease. A background poll (300-second default, 15–3600 configurable) validates **only previously attached sessions**, never all configured accounts. On a failed probe it transitions to `needs_assistance` and issues a nonsecret, one-time ticket; it holds the lease. The desktop receives only `account_id/ticket_id/reason/state` via bearer-protected `GET /api/v1/auth-assistance/pending`.

Once a human acknowledges a completed manual step, the same trusted monitor performs another world validation. If successful it moves the lease to authenticated. If unsuccessful a fresh ticket is required. The task ledger does not automatically resubmit ambiguous work or resume tasks. Shutdown stops polling and releases Daedalus's own host-local lease. Independent legacy clients may still have separate sessions; this is not cross-machine coordination.

The desktop shows an explicit monitor confirmation button only when a connected backend advertises monitoring. It polls only nonsecret tickets every 30 seconds and notifies each ticket once. It never exposes engine login material, browser cookies, password fields or raw errors.
