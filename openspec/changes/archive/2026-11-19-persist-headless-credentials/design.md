# Design — host-persistent secrets without graphical keyring

The authorized systemd system manager encrypts a fresh 256-bit host secret using `systemd-creds --with-key=host` into an owner-inaccessible, root-owned encrypted credential. At start, `LoadCredentialEncrypted` exposes 32 bytes only to the intended `User=debian` service in its `CREDENTIALS_DIRECTORY`. The API's fixed-account backend opts in explicitly with `DAEDALUS_PROTECTED_STORE_DIR`. When enabled, `_store` returns an AES-GCM adapter that writes ciphertext-only private files in a `0700` directory with owner-only `0600` records; service/user identities are additional authenticated data and hashed for filenames. Missing or corrupted keys and invalid signatures fail closed; there is no keyring/plaintext fallback for this mode.

The migration read the old Secret Service binding locally, located its private existing IkaBot saved file, performed a fresh TLS-verified, cookie-only player attestation, and copied the verified world cookie to ciphertext without logging either value. A synthetic systemd transient service validated key decryption, then a controlled backend restart with native Mac login was verified against Monjo's authenticated world and seven read-only city warehouses. The old unconfirmed passive alert receipt was inspected, backed up and marked `operator_reconciled` without reexecution. Service no longer has a VNC dependency. The physical host was not rebooted because it would interrupt unrelated bots; that and owner-supervised login/task acceptance remain open under `validate-live-authentication`.
